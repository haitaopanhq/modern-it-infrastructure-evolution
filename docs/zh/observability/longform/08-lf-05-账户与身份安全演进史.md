# 08-LF-05: 账户与身份安全演进史

## 信任边界如何从机器走向身份，又走向能力

很多技术概念，刚开始看都很碎。

账号、密码、Session、Cookie、LDAP、AD、SSO、OAuth、Token、IAM、Zero Trust、Workload Identity、AI Agent、模型能力保护……

它们像是一串很长的术语清单。

但如果把时间线拉长，就会发现它们其实都在回答同一个问题：

系统到底应该相信谁？相信多久？相信到什么程度？

账户与身份安全的历史，不是一堆工具替换史，而是一部“信任边界迁移史”。

它从一台机器开始，穿过内网、Web、企业系统、开放平台、云原生，又继续走向 AI Agent 和大模型时代。

安全边界从来没有消失。

它只是不断换了位置。

## 01 单机时代：一台机器，就是整个世界

最早的计算机世界很小。

一台机器，几个用户，一套本地账号系统。谁能登录这台机器，谁能读写文件，谁能拿到最高权限，就是安全问题的核心。

在 Unix / Linux 世界里，root 基本就代表最高控制权。拿到 root，就意味着可以读取文件、修改配置、安装程序、终止进程，甚至接管整台机器。

这一阶段的关键词很朴素：

User / Group、Permission、root / sudo、文件权限。

那时候的信任边界，就在机器内部。

你是谁？
你属于哪个组？
你能不能读这个文件？
你能不能写那个目录？

一切信任，都发生在这台机器里。

但历史不会停在一台机器里。机器一旦开始联网，安全的故事就被推向了更大的空间。

## 02 局域网时代：内网曾经是默认信任区

当机器连接成局域网后，信任边界开始从“机器”移动到“网络”。

很长一段时间里，企业默认相信一句话：

外网危险，内网可信。

于是，内网网段、防火墙、ACL、VPN、堡垒机、跳板机开始出现。它们共同构成了一个熟悉的安全模型：外面的人进不来，里面的人默认可信。

这个模型在早期确实有效。

因为系统少，网络边界清楚，员工设备相对固定，业务访问路径也不复杂。

但它有一个致命问题：

一旦攻击者进了内网，系统往往会给他过多信任。

账号被盗、VPN 凭证泄露、员工电脑中木马、内网服务器被攻破，都可能让攻击者开始横向移动。

所以局域网时代留下的最大教训是：

网络位置不等于可信身份。

人在内网，不代表他真的可信。

进入内网，也只是开始。

## 03 Web 时代：账号密码成为应用入口

Web 出现后，系统开始面向更多用户。

安全问题从“谁在这台机器上”变成了：

谁能访问这个应用？

于是账号、密码、Session、Cookie、登录态、RBAC 成为 Web 应用的基础能力。

HTTP 本身是无状态的。

你请求一次页面，服务器并不会天然记得你是谁。

但业务需要状态。

你登录之后，系统需要知道：

这是同一个用户。
他已经登录。
他正在访问自己的订单、后台、资料或工作台。

于是服务端生成 Session，浏览器保存 Cookie，登录态就这样被维持起来。

这一阶段最重要的分水岭是：

认证和授权被逐渐区分开来。

认证解决：你是谁。

授权解决：你能做什么。

很多安全事故，其实不是用户没登录，而是登录之后能访问不该访问的东西。

所以 Web 时代真正教会工程师的是：

账号密码只是入口，权限边界才是核心。

## 04 企业系统时代：统一身份，打破账号孤岛

企业系统越来越多后，问题又变了。

OA 一套账号，邮箱一套账号，CRM 一套账号，ERP 一套账号，研发平台又一套账号。

员工入职，要开一堆账号。

员工离职，要关一堆账号。

员工转岗，还要到处改权限。

只要漏掉一个系统，就可能留下安全隐患。

这就是典型的“账号孤岛”。

于是 LDAP、Active Directory、SSO、SAML、CAS、统一身份平台开始出现。

它们解决的不是某一个登录按钮，而是一个更大的企业治理问题：

把分散账号，收敛到统一身份入口。

统一开户。
统一禁用。
统一同步组织架构。
统一做权限审计。

从这个时候开始，身份不再只是一个应用里的账号，而变成了企业级基础设施。

但统一身份也带来了新的风险。

身份入口越集中，被攻破后的影响面也越大。

所以 SSO 不是终点。

它只是把分散风险，变成了集中治理。

## 05 开放平台时代：Token 成为新的钥匙

移动互联网和开放平台兴起后，系统之间的连接越来越多。

你用微信登录一个 App。
你授权第三方访问 GitHub。
你让自动化工具调用云资源。
你让日历应用读取日程。

这时候，用户不可能把主账号和密码交给每一个第三方应用。

于是 OAuth、OIDC、Access Token、Refresh Token、JWT 开始成为主流。

它们解决的问题是：

如何在不交出密码的情况下，把有限权限委托给别人。

Token 可以设置 Scope。

可以设置过期时间。

可以绑定资源范围。

也可以撤销。

这是一种巨大的进步。

但 Token 也因此变成了新的高价值资产。

过去攻击者偷密码。

后来攻击者开始偷 Token。

因为在很多系统里，拿到 Token，就等于拿到访问权。

所以开放平台时代的核心判断是：

Token 是新的钥匙。管好 Token，就是管住了访问权。

## 06 云与微服务时代：身份不再只属于人

进入云计算和微服务时代后，系统里的“主体”变多了。

不只是人访问系统。

服务会调用服务。
Pod 会调用数据库。
函数会调用对象存储。
CI/CD 会调用云 API。
监控系统会读取指标。
自动化任务会修改配置。

这时候，身份不再只属于人。

身份也属于服务、容器、工作负载、自动化流程和系统组件。

所以 Service Account、IAM Role、Workload Identity、SPIFFE、SPIRE、mTLS、Kubernetes RBAC、Cloud IAM 变得越来越重要。

云原生环境里，IP 不稳定，机器不固定，服务会动态伸缩，网络边界越来越模糊。

你不能再只问：

它从哪个 IP 来？

你必须追问：

它到底是谁？
它由谁签发？
它有没有权限？
它能访问什么资源？
它的行为是否可审计？

这就是 Workload Identity 的价值。

安全开始从“看来源”转向“看身份”。

## 07 Zero Trust：不再默认相信网络和一次登录

当系统复杂到一定程度后，人们终于意识到：

内网不可靠。
设备不可靠。
账号不一定可靠。
一次登录也不代表持续可靠。

Zero Trust 的工程含义，其实没有那么玄：

不要因为请求来自某个网络、某台设备、某个账号，就默认它可信。

每次访问，都应该结合上下文重新判断。

判断因素包括：

用户身份、设备状态、网络位置、访问资源、行为模式、风险等级、MFA 状态。

Zero Trust 强调持续验证、最小权限、动态授权和强审计。

但它真正难的，不是买一个 Zero Trust 产品。

真正难的是持续治理。

因为权限会漂移。
员工会转岗。
临时权限会变成永久权限。
测试账号会被遗忘。
Token 会散落在脚本里。
管理员会说一句：先方便一下。

很多安全体系最后不是败给黑客，而是败给组织惯性。

Zero Trust 最大的敌人，往往不是技术，而是“先方便一下”。

## 08 AIGC 大模型时代：保护对象从数据上移到能力本身

大模型出现后，安全保护的对象再次上移。

过去企业主要保护机器、网络、账号、Token、数据库、源代码和业务文档。

但 AIGC 时代出现了一个新的核心资产：

能力本身。

模型不是普通文件。

它沉淀了训练数据、业务知识、调优经验、推理模式和任务能力。

尤其在企业场景里，模型往往不是孤立存在的。它会和 RAG、Embedding、Vector DB、Prompt、AI Gateway、Tool Calling、业务流程连接在一起。

这些东西合起来，才是真正的 AI 能力资产。

过去企业最值钱的是数据库。

AI 时代，真正值钱的不只是数据，而是数据被组织、训练、调优之后形成的能力。

风险也因此变了。

模型复制。
能力蒸馏。
知识泄漏。
Prompt Injection。
RAG 污染。
推理接口滥用。

传统攻击偷的是数据。

AI 时代更隐蔽的攻击，是通过大量提问，把模型能力“学走”。

数据可以加密。
账号可以禁用。
Token 可以轮换。
权限可以回收。

但能力一旦被复制，往往很难追回。

所以这一阶段的安全重点，不再只是保护数据，而是保护能力本身。

## 09 AI Agent 时代：问题变成“谁代表谁行动”

如果说大模型让系统拥有了“能力”，那么 AI Agent 则让系统开始拥有“行动”。

传统系统大多按明确规则运行。

而 Agent 可以理解目标、拆解任务、调用工具、访问 API、读取文档、生成代码，甚至执行多步操作。

这时候，问题不再只是：

谁访问了系统？

而是：

谁代表谁在行动？

比如一个员工让 Agent 帮他处理任务。

Agent 查文档。
Agent 调接口。
Agent 创建工单。
Agent 生成代码。
Agent 触发部署。

这些行为到底算谁的？

是员工的行为？
是 Agent 的行为？
是平台的行为？
还是工具提供方的行为？

更关键的是，Agent 不应该默认继承用户的全部权限。

更合理的方式是：

按任务授权。
按工具授权。
按会话授权。
按资源授权。
按动作风险分级确认。

读文档，可以自动执行。
发邮件，需要确认。
删除数据，需要强确认。
触发部署，需要审批。

Agent 让机器拥有了行动权。

所以身份安全开始从“访问控制”，走向“行动委托控制”。

这一步非常关键。

因为未来真正危险的，不是 AI 会不会回答错，而是它能不能在错误的权限下执行真实动作。

## 10 AI Native 安全：从身份治理走向能力治理

最后，身份安全继续向前走。

如果说传统身份安全解决的是：

谁能访问什么资源？

那么 AI Native 安全还要继续追问：

谁能调用什么模型？
谁能访问什么知识库？
谁能使用什么工具？
谁能触发什么 Agent 流程？
谁能批量调用高价值能力？
谁能把输出结果用于再次训练？

这意味着，安全治理对象正在继续扩大。

从账号治理，到 Token 治理。

从 API 治理，到工作负载身份治理。

再到 Agent 身份、模型访问控制、知识库权限隔离和能力调用审计。

未来企业会越来越需要这些基础设施：

AI Gateway。
Prompt Audit。
Model Access Control。
RAG 权限隔离。
Vector DB 访问控制。
工具调用权限控制。
异常调用检测。
推理链路审计。
Secure Inference。

它们的目标，不是让 AI 更酷。

而是让 AI 能被企业安全地使用。

过去保护账号，是为了保护数据。

AI 时代保护模型，是为了保护能力。

## 尾声：信任边界一直在上移

如果把这 10 个阶段连起来看，就会发现一条很清晰的线索：

单机时代，信任边界在机器里。
局域网时代，信任边界在网络里。
Web 时代，信任边界在应用入口。
企业系统时代，信任边界在统一身份平台。
开放平台时代，信任边界在 Token。
云与微服务时代，信任边界在工作负载身份。
Zero Trust 时代，信任边界变成持续判断。
AIGC 大模型时代，信任边界上移到能力本身。
AI Agent 时代，信任边界开始进入行动委托。
AI Native 时代，信任边界最终走向模型、知识、工具和流程的综合治理。

这就是账户与身份安全演进史最值得记住的地方：

它不是一部“登录技术史”。

也不是一部“权限系统史”。

它更像一部数字世界的文明史。

每一次系统变复杂，信任就要被重新定义。

每一次能力被释放，边界就必须重新建立。

每一次连接变多，身份就会变得更重要。

技术在演进，风险也在演进。

但真正不变的问题始终是那个：

你是谁？你代表谁？你能做什么？你做过什么？

到了 AI 时代，还要再加一句：

你调用的能力，是否应该属于你？
